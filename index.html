Sistemas Operativos

Unidad 6: Protección y Seguridad

Tema 6.1

Concepto y Objetivos de Protección y Seguridad

Aunque a menudo se usan como sinónimos, en el contexto de los sistemas operativos (basado en Tanenbaum y Stallings), protección y seguridad tienen distinciones claras.

Protección

Se refiere a los mecanismos específicos del sistema operativo que controlan el acceso de los programas, procesos o usuarios a los recursos del sistema (CPU, memoria, archivos). Su objetivo principal es asegurar que los usuarios y procesos activos no interfieran entre sí.

Seguridad

Es un concepto más amplio. Involucra la confianza en que el sistema funcionará como se espera y estará protegido contra ataques tanto internos como externos. Incluye factores del entorno físico, redes, y factor humano.

Objetivos Principales

  • Confidencialidad: Garantizar que la información solo sea accesible por las personas autorizadas (prevención del robo de datos).
  • Integridad: Proteger los datos contra modificaciones no autorizadas (prevenir manipulación).
  • Disponibilidad: Asegurar que los recursos del sistema estén disponibles para los usuarios autorizados cuando los necesiten (evitar ataques de denegación de servicio).
Tema 6.2

Clasificación Aplicada a la Seguridad

La seguridad de un sistema informático debe abordarse desde múltiples frentes. Si un solo eslabón de la cadena falla, todo el sistema puede quedar expuesto.

1. Niveles de Seguridad

Física

Protección de las instalaciones donde se alojan los sistemas (controles de acceso, protección contra incendios, etc.).

Humana

Autorización adecuada de usuarios y prevención de ingeniería social. Evitar que usuarios legítimos comprometan el sistema por error o malicia.

Redes

Protección de la información mientras se transmite. Uso de firewalls, VPNs e IDS/IPS.

Sistema Operativo

Protección a nivel lógico: autenticación, control de accesos a memoria y sistemas de archivos.

2. Clasificación de Amenazas (Según su efecto)

  • Interrupción: Un recurso del sistema es destruido o se vuelve indisponible (ataca la disponibilidad).
  • Intercepción: Una parte no autorizada consigue acceso a un recurso (ataca la confidencialidad).
  • Modificación: Una parte no autorizada altera los datos de un recurso (ataca la integridad).
  • Invención / Fabricación: Se insertan objetos falsificados en el sistema (ataca la autenticidad e integridad).
Tema 6.3

Funciones del Sistema de Protección

El sistema operativo implementa una serie de funciones fundamentales para hacer cumplir las políticas de seguridad. Según el principio de mínimo privilegio, un programa o usuario solo debe tener los permisos estrictamente necesarios para realizar su tarea.

1. Autenticación (Authentication)

Es el proceso de verificar que un usuario o proceso es realmente quien dice ser. Puede basarse en algo que el usuario sabe (contraseña), algo que tiene (token/tarjeta) o algo que es (biometría).

2. Autorización (Authorization)

Una vez autenticado, el sistema debe determinar si ese usuario tiene los permisos necesarios para realizar una acción específica (leer un archivo, ejecutar un programa).

3. Auditoría (Auditing)

El sistema operativo debe registrar las actividades relacionadas con la seguridad en un archivo de registro (log). Esto permite investigar brechas de seguridad y detectar comportamientos anómalos o intentos repetidos de acceso fallido.

4. Aislamiento

Mantener los procesos de diferentes usuarios separados en la memoria virtual, evitando que un proceso lea o modifique el espacio de direcciones de otro.

Tema 6.4

Implantación de Matrices de Acceso

El modelo más común para representar esquemas de protección es la Matriz de Control de Acceso. En este modelo conceptual:

  • Las filas (Dominios/Sujetos): Representan a los usuarios o procesos.
  • Las columnas (Objetos): Representan los recursos (archivos, impresoras, memoria).
  • Las celdas: Contienen los derechos de acceso (Lectura, Escritura, Ejecución) que tiene el sujeto sobre el objeto.

Formas de Implementación

Dado que en sistemas reales una matriz completa sería enorme y estaría casi vacía (matriz dispersa o sparse matrix), se implementa de otras maneras más eficientes:

Listas de Control de Acceso (ACL)

La matriz se descompone por columnas. A cada objeto (ej. un archivo) se le asocia una lista que especifica qué sujetos tienen acceso a él y con qué derechos. (Muy usado en Windows y Linux/UNIX).

Listas de Capacidades

La matriz se descompone por filas. A cada sujeto (proceso/usuario) se le asocia una lista que indica a qué objetos puede acceder y con qué operaciones. Es como tener un "llavero" con llaves específicas para ciertas puertas.

Tema 6.5

Protección Basada en el Lenguaje

Tradicionalmente, la protección es responsabilidad exclusiva del núcleo (kernel) del Sistema Operativo. Sin embargo, a medida que los sistemas evolucionan, los lenguajes de programación modernos asumen un papel crucial en la seguridad, proporcionando validaciones mucho antes de que se interactúe con el SO.

Ventajas del enfoque basado en lenguaje

  • Menor sobrecarga (Overhead): Validar tipos y rangos en tiempo de compilación o mediante la máquina virtual del lenguaje evita llamadas constantes al sistema operativo.
  • Flexibilidad: Permite definir políticas de seguridad mucho más finas a nivel de objetos de software, no solo a nivel de archivos de disco.

Mecanismos comunes:

  • Seguridad de Tipos (Type Safety): Lenguajes como Java o C# impiden que un programa acceda a zonas de memoria que no le corresponden, evitando errores críticos como el desbordamiento de búfer (Buffer Overflow), muy común en C o C++.
  • Sandboxing: Ejecución de código (especialmente código no confiable descargado de internet) en un entorno restringido o "caja de arena". Java utiliza gestores de seguridad que interceptan y evalúan si una instrucción (como leer un archivo local) está permitida según la política definida.
Tema 6.6

Validación y Amenazas al Sistema

La seguridad de un sistema depende críticamente de validar quién accede y de protegerlo contra amenazas (programas maliciosos o malware) diseñadas para romper las reglas de protección.

Métodos de Validación (Autenticación)

Contraseñas (Passwords) Preguntas de seguridad Tarjetas Inteligentes (Tokens) Biometría (Huellas, Retina) MFA (Autenticación Multifactor)

Amenazas Comunes (Software Malicioso)

Caballo de Troya (Trojans)

Programa aparentemente útil e inofensivo, pero que contiene código oculto que, al ejecutarse, realiza funciones no deseadas (como abrir un puerto trasero o robar datos). Depende de que el usuario lo ejecute.

Virus

Fragmento de código incrustado en un programa legítimo. Se reproduce a sí mismo insertando copias en otros programas y necesita intervención humana (como abrir un archivo) para propagarse.

Gusanos (Worms)

Programa independiente (no requiere anfitrión) que se reproduce a través de redes, explotando vulnerabilidades del sistema operativo para saltar de máquina en máquina de forma automática.

Puertas Traseras (Trapdoors / Backdoors)

Puntos de entrada no documentados creados deliberadamente por los desarrolladores (o insertados por atacantes) que permiten saltarse los procedimientos normales de autenticación.

Tema 6.7

Cifrado (Criptografía)

Cuando los mecanismos de control de acceso del SO no son suficientes (por ejemplo, si alguien roba el disco duro físico o intercepta información en la red), el cifrado es la principal línea de defensa. Consiste en transformar datos en claro a un formato ininteligible.

Cifrado Simétrico

Se utiliza la misma clave tanto para cifrar como para descifrar. Ambos extremos de la comunicación deben mantener esta clave en absoluto secreto.

  • Ventajas: Muy rápido y eficiente, ideal para grandes volúmenes de datos.
  • Desventajas: El problema de distribuir la clave de forma segura.
  • Ejemplos: AES (Advanced Encryption Standard), DES.

Cifrado Asimétrico (Clave Pública)

Se utiliza un par de claves: una pública (conocida por todos) y una privada (secreta del usuario). Lo que se cifra con una, solo se puede descifrar con la otra.

  • Ventajas: Resuelve el problema de la distribución de claves y permite firmas digitales.
  • Desventajas: Computacionalmente muy pesado y lento comparado con el simétrico.
  • Ejemplos: RSA, Criptografía de Curva Elíptica (ECC).

Funciones Hash (Unidireccionales): Algoritmos (como SHA-256) que generan una "huella digital" de un archivo. No sirven para ocultar datos, sino para garantizar la integridad (saber si un archivo fue modificado).
